# 证据与分流

## 证据等级

README 的关键主张应选择与证据相称的措辞。不要把较低等级的证据升级为“已验证”。

| 等级 | 可接受证据 | 可以写什么 | 不能推出什么 |
| --- | --- | --- | --- |
| A：行为已验证 | 本次本地执行结果、受控测试、可访问的本地服务、生成物、可复现评测，或本次检查过的官方公开 Demo | “本次验证可运行/可访问”“示例输出为” | 对未覆盖的平台、规模、生产环境作保证 |
| B：实现已检查 | 当前代码、配置、清单、测试定义、版本文件、模型卡或数据说明 | “仓库提供”“配置声明”“实现包含” | 功能一定可用、性能一定达标、外部服务一定可访问 |
| C：来源声明 | 官方发布页、论文、历史截图、第三方资料或尚未实测的在线说明 | “官方说明”“据发布说明”“待本地验证” | 当前环境已复现、结论适用于当前版本 |

目录树属于 B 级：可用来解释项目构成或导航，不能作为功能、质量、性能、兼容性或安全性的证明。

## 验证选择

按以下优先级选择最小证据，不必为了完整而跑全部流程：

1. 已有单测、示例数据、dry-run、构建检查或本地开发服务。
2. 可逆的本地 CLI、库调用、页面预览、导入检查或生成临时产物。
3. 已存在的官方公开 Demo、文档或发布资产，只能作为 C 级来源，除非本次实际访问并检查。

停止条件：已能证明 README 最小路径中的关键结果，或继续验证会触发外部副作用、真实数据、费用、发布或不可逆状态。后一种情况下停止，并如实写明验证边界。

## 多读者分流

README 的首屏服务一个首要读者；可以为其他读者提供链接，但不承载其完整教程。

| 读者 | README 应给出的最小入口 | 应下沉的位置 |
| --- | --- | --- |
| 使用者 | 获取方式、最短体验、帮助入口 | 使用手册、FAQ |
| 部署者 | 支持的部署模式、前置条件、部署文档链接 | 运维、配置、安全、迁移文档 |
| 调用者 | 安装、最小调用、契约链接 | API 参考、高级用法 |
| 贡献者 | 贡献范围和 `CONTRIBUTING.md` 链接 | 开发环境、测试、发布流程 |
| 评估者 | 任务边界、证据、Demo 或基准入口 | 评测协议、数据卡、模型卡、研究报告 |

有两个主要读者时，可以在 README 使用两个简短入口。出现三个或更多读者时，先给读者选择，再链接到各自文档；不要在 README 并排铺开多份完整流程。
